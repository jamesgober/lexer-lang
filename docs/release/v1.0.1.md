# lexer-lang v1.0.1: Positions past 4 GiB

**Patch.** Fixes position handling for texts over 4 GiB. No public item changes, and texts that fit in 4 GiB lex exactly as before.

## What is lexer-lang?

The hand-written-lexer toolkit for the family: a `Cursor` over source text with peeking, bumping and run-eating, and token emission with spans in a `source-lang` map's global position space.

## Fixed

Spans are `u32` byte positions, so the family addresses up to 4 GiB of source. `Cursor::new` and `Cursor::with_base` accept any `&str`, though, and the cursor turned its local byte offset into a `u32` with a plain cast. On a text over 4 GiB the offset wrapped:

- a token that crossed the 4 GiB mark got a span that ended near zero;
- `lexeme` sliced from the token start to the wrapped offset, which runs backwards, and panicked.

Only the `base + offset` addition saturated, although the docs said every position did.

The cursor now keeps local offsets as `usize`. `lexeme` and `remaining` are exact at any size, and every reported position past `u32::MAX` is `u32::MAX`, as documented. A test lexes a token across the 4 GiB mark; it allocates 4 GiB, so it is ignored by default (`cargo test --release --test huge -- --ignored`), and a unit test checks the conversion on every run.

## Compatibility

No public API change. MSRV stays at Rust 1.85.
